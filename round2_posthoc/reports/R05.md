## 3. How hard the machine looked

- bit-level circuit width(s): [39] bits; transactions per search: [3]; users: 2; loops unrolled up to 8 times
- fuzzer: random sequences of 4 transactions on the real EVM (numbers of any size)
- exact search: 1, 2 and 3 transactions from the deployed state at full 256-bit size

- model check: 363 random transactions run on both the circuit and the real EVM; 0 disagreements

- run time: 123.1 s

## 5. Findings: attacks the real EVM confirmed

### `withdraw_fee_floor`

Rule: `called("withdraw") and ok and ((arg(1) < pre("minFee")))`

Found by: fuzzing on the EVM (fuzz 4tx)

Attack:

1. `MockToken.approve(50, 256) from 0x31`
2. `MockToken.transferFrom(728815563385977040452943777879061427756277306518, 152, 730750818665451459101842416358141509827966271488) from 0x31` (reverted: no effect)
3. `withdraw(100000000, 136, 999) from 0x31`

What the real EVM did (values that changed, before -> after):

- tx 1: MockToken.allowance[U0][U1]: 0 -> 256
- tx 2 (reverted): nothing changed
- tx 3: BridgeGateway.balanceOf[U0]: 100000000000 -> 99899999864, BridgeGateway.feesAccrued: 0 -> 136, BridgeGateway.nonce: 0 -> 1, MockToken.balanceOf[BridgeGateway]: 100000000000 -> 99900000000, MockToken.balanceOf[U0]: 0 -> 100000000

Triage by the rule writer: **real_bug**: setMinFee reverted, so minFee is the deployer's value, yet withdraw accepted fee 112 below it; withdraw never enforces minFee (and accepts negative fees).

### `withdraw_debit_covers_quantity`

Rule: `ok and called("withdraw") and pre("balanceOf", sender) - post("balanceOf", sender) < arg(0)`

Found by: fuzzing on the EVM (fuzz 4tx)

Attack:

1. `MockToken.mint(49, 1461501637330902918203684832716283019655932542976) from 0x31` (reverted: no effect)
2. `withdraw(2732304826, 115792089237316195423570985008687907853269984665640564039457584007911749688004 (= -1379951932 if signed), 65537) from 0x31`

What the real EVM did (values that changed, before -> after):

- tx 1 (reverted): nothing changed
- tx 2: BridgeGateway.balanceOf[U0]: 100000000000 -> 98647647106, BridgeGateway.nonce: 0 -> 1, MockToken.balanceOf[BridgeGateway]: 100000000000 -> 97267695174, MockToken.balanceOf[U0]: 0 -> 2732304826

Triage by the rule writer: **real_bug**: With fee = -1379951932, withdraw debits only quantity + fee yet transfers the full quantity, so the user receives 1379951932 more tokens than they are debited; a negative fee should be rejected (and fee should be >= minFee).
